# Spec Delta

## MODIFIED Requirements

### Requirement: 問題画面の表示
司会画面は現在の問題について、問題番号と総問題数、問題名、説明、各選択肢の写真と選択肢の説明を表示順に表示しなければならない（MUST）。正解発表前は、どの写真がどのラベルかを読み取れる情報（ラベルの帯、ラベルを持つ属性、ラベルを含む代替テキスト）を画面に置いてはならない（MUST NOT）。

#### Scenario: 第 1 問を問題番号つきで表示する
- **WHEN** タイトル画面から第 1 問へ進む
- **THEN** 第 1 問の問題名・説明・全選択肢の写真と選択肢の説明が表示順に、および「1 / 総問題数」が表示される

#### Scenario: 正解発表前は正解情報を表示しない
- **WHEN** 問題を表示し、まだ正解発表をしていない
- **THEN** 正解の印、順位、銘柄、価格、解説はどれも表示されない

#### Scenario: 正解発表後に移動して戻るとラベルを表示しない
- **WHEN** 第 1 問で正解発表をしてから「次へ」、続けて「前へ」を押す
- **THEN** どの選択肢の要素にもラベルの帯（`.label-bar`）と `data-label` 属性がなく、写真の代替テキストがラベル（`選択肢 A` の形）を含まない

#### Scenario: 正解発表前はラベルを表示しない
- **WHEN** 問題を表示し、まだ正解発表をしていない
- **THEN** どの選択肢の要素にもラベルの帯（`.label-bar`）と `data-label` 属性がなく、写真の代替テキストがラベル（`選択肢 A` の形）を含まない

### Requirement: pick の正解発表
`pick` の問題で正解発表をすると、司会画面は各選択肢を発表前と同じ位置に置いたまま、各選択肢にラベルを表示し、`rank: 1` の選択肢に「正解」の印を付け、全選択肢の銘柄と価格、正解ラベルと解説を表示しなければならない（MUST）。正解の選択肢は色だけでなく文字の印でも区別できなければならない（MUST）。

#### Scenario: pick の正解発表で各選択肢にラベルを表示する
- **WHEN** 選択肢を B・A のラベルの順に書いた `pick` の問題で「正解発表」を押す
- **THEN** 1 番目の選択肢に B、2 番目の選択肢に A のラベルが表示される

#### Scenario: pick の正解発表で選択肢の位置は変わらない
- **WHEN** `pick` の問題で「正解発表」を押す
- **THEN** 各選択肢の写真は発表前と同じ順で、発表前と同じ座標と大きさで表示される

#### Scenario: pick で正解の選択肢に正解の印が付く
- **WHEN** 選択肢 B が `rank: 1` の `pick` の問題で「正解発表」を押す
- **THEN** 選択肢 B に「正解」の文字の印が表示され、選択肢 A には表示されない

#### Scenario: pick の正解発表で全選択肢の銘柄と価格を表示する
- **WHEN** `pick` の問題で「正解発表」を押す
- **THEN** すべての選択肢にそれぞれの銘柄と価格が表示される

#### Scenario: pick の正解発表で正解ラベルと解説を表示する
- **WHEN** 選択肢 B が `rank: 1` の `pick` の問題で「正解発表」を押す
- **THEN** 「正解は B」とその問題の解説が表示される

### Requirement: order の正解発表
`order` の問題で正解発表をすると、司会画面は各選択肢を発表前と同じ位置に置いたまま、全選択肢にラベル・順位・銘柄・価格を表示し、`rank: 1` の選択肢に「正解」の印を付け、rank の昇順に並べたラベル列と解説を表示しなければならない（MUST）。

#### Scenario: order の正解発表で各選択肢にラベルを表示する
- **WHEN** 選択肢を C・A・B のラベルの順に書いた `order` の問題で「正解発表」を押す
- **THEN** 1 番目・2 番目・3 番目の選択肢にそれぞれ C・A・B のラベルが表示される

#### Scenario: order の正解発表で 1 位の選択肢に正解の印が付く
- **WHEN** A、B、C の `rank` が 1、3、2 の `order` の問題で「正解発表」を押す
- **THEN** 選択肢 A に「正解」の文字の印が表示され、B と C には表示されない

#### Scenario: order の正解発表で全選択肢に順位を表示する
- **WHEN** A、B、C の `rank` が 1、3、2 の `order` の問題で「正解発表」を押す
- **THEN** A に 1 位、B に 3 位、C に 2 位が、それぞれの銘柄と価格とともに表示される

#### Scenario: order の正解発表で正解の並びと解説を表示する
- **WHEN** A、B、C の `rank` が 1、3、2 の `order` の問題で「正解発表」を押す
- **THEN** 「正解は A → C → B」とその問題の解説が表示される

### Requirement: 正解発表の再演出
正解発表後に再び正解発表を操作すると、司会画面は正解発表の演出（紙吹雪と正解の印の点滅）を最初からもう一度再生しなければならない（MUST）。表示する正解情報（ラベル・正解の印・順位・銘柄・価格・解説）は変えてはならない（MUST NOT）。動きを減らす OS の設定（reduced motion）が有効なときは、演出を再生しない。

#### Scenario: 正解発表をもう一度押すと演出を再生する
- **WHEN** 正解発表をした問題で、もう一度「正解発表」を押す
- **THEN** 紙吹雪と正解の印の点滅が最初から再生される

#### Scenario: 正解発表をもう一度押しても正解情報は変わらない
- **WHEN** 正解発表をした問題で、もう一度「正解発表」を押す
- **THEN** ラベル・正解の印・順位・銘柄・価格・解説は 1 回目の正解発表後と同じである

#### Scenario: reduced motion が有効なときは演出を再生しない
- **WHEN** reduced motion が有効な環境で「正解発表」を押す
- **THEN** 紙吹雪と点滅は再生されず、正解情報は表示される

### Requirement: 投影時の可読性
司会画面は 16:9 の領域に収まるよう配置し、明るい部屋のプロジェクタで読めるコントラストでなければならない（MUST）。タイトル・問題名・説明・選択肢の説明・解説の文字と背景のコントラスト比は 4.5:1 以上とする。

#### Scenario: 1920×1080 の表示で正解発表前の全要素が 1 画面に収まる
- **WHEN** 1920×1080 のビューポートで 3 択の問題を正解発表前の状態で表示する
- **THEN** 問題名・説明・全選択肢の写真と選択肢の説明・操作ボタンがスクロールなしで表示される

#### Scenario: 1920×1080 の表示で全要素が 1 画面に収まる
- **WHEN** 1920×1080 のビューポートで 3 択の問題の正解発表をする
- **THEN** 問題名・全選択肢・解説・操作ボタンがスクロールなしで表示される

#### Scenario: 1920×1080 の表示でタイトル画面が 1 画面に収まる
- **WHEN** 1920×1080 のビューポートでタイトル画面を表示する
- **THEN** タイトル・QR コード・操作ボタンがスクロールなしで表示される

#### Scenario: 文字と背景のコントラスト比が 4.5:1 以上である
- **WHEN** 司会画面のタイトル・問題名・説明・選択肢の説明・解説の文字色と背景色のコントラスト比を測る
- **THEN** どれも 4.5:1 以上である
