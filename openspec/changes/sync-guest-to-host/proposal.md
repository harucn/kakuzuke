# Proposal

## Why

今の参加者画面は司会画面と連動しない。参加者は自分で問題を進め、正解は会場のプロジェクタでしか見られない。参加者のスマホも司会の進行どおりに切り替え、正解発表を手元でも見られるようにする（sharpen.md の Sharpened）。

## What Changes

- サーバーの Durable Object「会場」が、司会の状態（タイトル・出題中・正解発表と問題番号）を持つ唯一の場所になる。司会画面と参加者画面は WebSocket でつながり、状態が変わるたびに全員へ届く。
- **BREAKING** 司会画面の状態はタブの `sessionStorage` ではなく会場が持つ。再読み込みしても、新しいタブで開いても、2 枚目の司会画面を開いても、会場の今の状態（正解発表中ならその表示）が出る。
- **BREAKING** 参加者画面から前へ・次へ・はじめるのボタンをなくし、司会の状態に完全に追従させる。途中から開いた参加者は今の画面から始まる。
- 参加者画面の正解発表で、司会画面と同じ情報（ラベル・正解の印・順位・銘柄・価格・解説・「正解は B」）と紙吹雪を出す。
- 正解は発表した問題の分だけ、発表したときに WebSocket で届ける。参加者に届く HTML と JS には、これまでどおり正解を含めない。司会画面も正解を同じ経路で受け取り、`/host` の HTML と認証なしのサーバー関数から正解をなくす。
- 会場の状態は、それを作った問題セットに結び付ける。問題セットを変えてデプロイしたら会場はタイトル画面に戻り、古い版を開いたままの画面は読み込み直す。
- 接続が切れたら自動で再接続し、切れている間は両画面に「再接続中」と出す。司会画面は接続が切れている間は操作できない。
- 範囲外: 操作の認証（`/host` を知る人が操作できる今の扱いを続ける）、複数の会場を同時に開くこと、参加者の回答の集計。

## Capabilities

### New Capabilities

- `venue-sync`: 会場の進行状態を 1 か所で持ち、つながっている全画面へ配る仕組み。状態の保存、途中参加と再接続、問題セットが変わったときの扱い、参加者へ送る正解の範囲を定める。

### Modified Capabilities

- `host-screen`: 再読み込みで同じ問題に戻る要件を、会場の状態を表示する要件に置き換える。新しいタブで開いたときもタイトル画面ではなく会場の状態を出す。接続が切れている間の表示と操作の扱いを足す。
- `guest-screen`: 正解情報を一切出さない要件を「正解発表前は出さない」に改め、正解発表の表示と紙吹雪を足す。届くデータの制約を「発表していない問題の正解を含めない」に改める。前後の画面への移動を、司会画面への追従に置き換える。タイトル画面から「はじめる」をなくす。

## Impact

- コード: Durable Object とその WebSocket の受け口（`src/server.ts` を新設）、`wrangler.jsonc`（binding と migration）、`src/question-set/vite-plugin.ts`（問題セットの版）、`src/host/`（状態機械をサーバーへ移す・`restore.ts` と `host-data.functions.ts` を削除）、`src/guest/GuestScreen.tsx`、`reveal.ts` と `Celebration.tsx` を両画面の共通部品へ移す、`src/styles/theme.css`。
- 運用: Cloudflare の Durable Objects を使う。会場は 1 つだけで、状態はデプロイをまたいで残る。README の操作説明を直す。
- テスト: E2E は会場を共有するので、直列に流し、テストごとに会場をタイトル画面へ戻す。デプロイ先に向けて流すときは会場を動かすテストを skip する。型検査を `pnpm typecheck` にまとめ、CI でも流す。
- 完了の判定は sharpen.md の Done Means。
  - 単体テスト: サーバーの状態機械、参加者へ送る状態に発表前の正解を含まないこと。
  - E2E: 司会 1 つ・参加者 2 つの同期、途中参加、再接続、HTTP 応答と WebSocket フレームの漏洩検査、幅 360px の正解発表。
  - 実機のスマホ: プレビュー環境で、司会の操作に追従することとスリープ復帰後に追いつくことを確かめる。
