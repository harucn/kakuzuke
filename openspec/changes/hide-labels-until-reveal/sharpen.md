# Sharpen

## Request

> 画面に表示するものをこんな感じにしたい。整理できてるかな？
> 進行側
> ・正解発表前はABCなしで写真と解説
> ・正解発表したらABCを出したい
> ・一番高い？いい？やつにフォーカスは今まで通り
>
> 回答者側
> ・進行側と一緒で問題と選択肢の説明があればいいかな

対話で確定した前提（ユーザー回答の要約）:

- 写真を見れば商品が分かるので、どの写真が A・B・C かを正解発表まで伏せる。
- 発表前に出す「解説」は今の解説（答えを含む）とは別の、選択肢ごとの説明である。
- 発表後の表示（正解の印・銘柄・価格・順位・解説）は今まで通り。銘柄・価格は引き続き秘密。
- 表示順は YAML に書いた順。ラベルは作者が選択肢ごとに書く。選択肢の説明は必須。

## Sharpened

正解発表まで、どの写真が A・B・C かを司会画面にも参加者画面にも出さない。

- **問題データ**: 選択肢は表示順に書き、各選択肢にラベル `label`（A・B・C）と、答えを含まない選択肢の説明 `note` を持たせる。ラベルは選択肢数を n として A から n 番目までを 1 回ずつ使う。`note` は必須で、参加者に見えるので銘柄・価格・解説の文字列を含めるとビルドが失敗する。
- **司会画面の発表前**: 問題名・説明・写真・選択肢の説明を表示順に出す。ラベル・正解の印・銘柄・価格・順位・解説は出さない。
- **司会画面の発表後**: カードの位置はそのままで各カードにラベルを出し、`rank: 1` に正解の印を付ける。銘柄・価格・順位（order）・解説・「正解は B」は今まで通り出す。
- **参加者画面**: 司会画面の発表前と同じ内容。届くデータに `label`・`rank`・`name`・`price`・解説を含めない。
- **範囲外**: 銘柄名を発表前に見せること、表示順の自動並べ替え、司会画面と参加者画面の同期。

## Current System

- 選択肢のラベルは作者が書かず、`toQuestionSet` が書いた順に A・B・C を付ける（`src/question-set/parse.ts:173`）。表示順もこの順なので、ラベルと表示位置が常に一致する。
- 選択肢のスキーマは `{ image, rank, name, price }`（`src/question-set/parse.ts:44`）。選択肢ごとの公開してよい説明はない。
- 公開形の選択肢は `label` と `image`（`src/question-set/model.ts:43`、`PUBLIC_OPTION_KEYS` は `src/question-set/model.ts:52`）。参加者画面はラベルを受け取って表示する。
- `OptionCard` は常にラベルの帯を出し、`data-label` 属性と `alt="選択肢 A"` を付ける（`src/ui/OptionCard.tsx:19`）。司会画面の発表前（`src/host/HostScreen.tsx:107`）も参加者画面（`src/guest/GuestScreen.tsx:84`）も同じ部品を使う。
- 発表後の表示は `revealView` が作り、`answerOf` で rank 順のラベル列から見出しと正解の印を決める（`src/host/reveal.ts:20`、`src/question-set/model.ts:79`）。どちらもラベルで選択肢を引くので、表示順とラベルが分かれても動く。
- 漏洩検査は文字列（銘柄・価格・解説）の走査と、公開データのキーが許可リストと完全一致するかの構造検査の 2 本（`tests/build/leak.test.ts:115`、`:135`）。ラベルは 1 文字なので文字列走査では捕まえられず、構造検査で守る。
- `public-text-leak` はタイトル・問題名・説明を検査する（`src/question-set/parse.ts:126`）。
- E2E はラベルで選択肢を引く（`tests/e2e/host.spec.ts:19`、`tests/e2e/guest.spec.ts:17`、`tests/e2e/content.spec.ts:31`）。

## Done Means

- 単体テストで、`label` の欠落・重複・範囲外と `note` の欠落・空・銘柄などの混入がビルドエラーになり、公開形の選択肢が `image` と `note` だけを表示順で持つことを確かめる。
- ビルドの漏洩検査で、公開データの選択肢のキーが `image`・`note` と完全一致し、`label` を持たないことを確かめる。
- E2E で、司会画面の発表前と参加者画面の DOM にラベルの帯・`data-label`・ラベルを含む代替テキストがないこと、発表後に同じ位置のカードへ正しいラベルと正解の印が出ることを確かめる。1920×1080 と幅 360px に収まることを確かめる。
- `pnpm exec tsc --noEmit`・`pnpm test`・`pnpm e2e`・`pnpm build` が通る。
