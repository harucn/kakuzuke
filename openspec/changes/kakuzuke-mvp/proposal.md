# Proposal

## Why

結婚式二次会の格付けチェックで、現物の出題を補助する Web アプリの MVP を作る。司会は問題・選択肢・正解と解説を投影で見せる手段が、参加者は自分のスマホで問題と選択肢の写真を確かめる手段がそれぞれ必要で、参加者には正解が漏れてはならない。

## What Changes

- 問題データを 1 セット、リポジトリ内のファイルとして定義し、スキーマで検証する。問題は `mode`（`pick` = 最も高いものを 1 つ当てる / `order` = 全選択肢の順位を当てる）、問題名、説明、解説、選択肢 2〜3 個（`rank`、`name`、`price`）を持つ。選択肢のラベル A/B/C と写真のファイル名（`q1-a.jpg` など）は並び順から決まる。
- 司会画面（投影用 16:9）を追加する。画面内ボタンとキーボード（← / → / PageUp / PageDown / Space / Enter）で前へ / 次へ / 正解発表を操作し、正解発表で正解の印・各選択肢の銘柄と価格（`order` では順位）・解説を出す。全画面表示に対応する。
- 参加者画面（スマホ）を追加する。問題名・説明・選択肢の写真を前へ / 次へで順に見る。司会画面とは同期しない。
- 参加者画面に届くデータ（HTML・JS・参加者画面を進める間の応答）から `rank`・`name`・`price`・解説を除く。問題名と説明にも銘柄・価格・解説の文字列を書かない。
- 見た目はクリーム地 × 味道園グリーン × 赤のドット調（DotGothic16）で、明るい会場のプロジェクタで読めるようにする。正解は色だけでなく印と文字でも示す。参照: `mockup.html`。
- TanStack Start で作り、Cloudflare Workers にデプロイする。
- 範囲外: 投票、ランク判定、音声、管理画面、司会画面の URL 秘匿、画面同期、複数の問題セット。
- 未決定: `pick` と `order` のどちらを MVP の出題に使うか。データ構造と画面は両方に対応する。

## Capabilities

### New Capabilities

- `question-set`: 問題セットのデータ形式、検証規則（選択肢数・順位・写真の存在）、参加者向けに正解情報を除いた公開形への変換。
- `host-screen`: 投影用の司会画面。問題の表示、前後移動、正解発表（`pick` / `order` の発表内容）、キーボード操作、全画面表示。
- `guest-screen`: 参加者のスマホ画面。問題と選択肢の写真の表示、前後移動、正解情報を受け取らないこと。

### Modified Capabilities

なし（既存の spec はない）。

## Impact

- 新規コード: TanStack Start アプリ一式（`package.json`、ルート、問題データ、画像、スタイル）、Cloudflare Workers 設定（`wrangler` 設定ファイル）。
- 依存の追加: TanStack Start / React、zod（スキーマ検証）、yaml（問題ファイルの読み込み、ビルド時のみ）、Vitest、Playwright、wrangler、Google Fonts（DotGothic16・Silkscreen）。
- 外部システム: Cloudflare アカウントへのデプロイ。
- 完了の判定（sharpen の Done Means）:
  - 問題データの検証テストが正しいデータで通り、壊れたデータ（`rank: 1` がない・重複、選択肢が 1 個や 4 個、写真ファイルがない、問題名や説明に価格を含む）で失敗する。
  - 参加者に届く問題データが `rank`・`name`・`price`・解説を持たないこと、ビルド成果物のクライアント向けファイル（司会画面の HTML を除く）と参加者画面を進める間の応答に銘柄・価格・解説の文字列が含まれないことをテストで確認する。
  - Playwright の E2E で、司会画面と参加者画面をそれぞれ最初から最後まで進められ、司会画面で各問題の正解発表ができる。キーボード操作でも同じことができる。
  - デプロイした URL を、明るい部屋のプロジェクタとスマホ数台の実機で最後まで進めて確認する。
